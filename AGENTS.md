## 2. Architecture (ADR-001)

Modular monolith. All domain rules are **pure functions** in
`backend/src/domain/<area>/` (no DB, no HTTP), so they are unit-testable for the
coverage bonus. Route files in `backend/src/routes/audit/<area>.js` validate
input, load state from Postgres, call the pure functions, persist, and respond.

```
docker-compose.yml   postgres:16-alpine, redis:7-alpine, minio (bitnamilegacy mirror),
                     api (backend image, host port 8080), worker (same image, node src/worker.js)
backend/
  Dockerfile         node:20-alpine, npm ci --omit=dev
  jest.config.js     tests live in repo-root tests/, coverage of backend/src/domain + lib
  scripts/coverage-areas.js   writes COVERAGE.json from coverage/coverage-summary.json
  src/
    server.js        wait for DB -> migrate -> resetAndSeed -> listen :8080
    app.js           CORS, express.json({limit:'1mb'}), /health, /audit/v1, /api/v1 (rate limited), 404, errorHandler
    worker.js        reads Redis stream "domain-events" and inserts into domain_events table
    db/pool.js       pg Pool, query(), tx(fn) transaction helper
    db/schema.js     CREATE TABLE IF NOT EXISTS ... (JSONB heavy). RESET_TABLES list.
    db/seedData.js   exact baseline ids of spec 5.5 / 8.3 (sports, tenants, leagues, clubs, players, users, store)
    db/reset.js      migrate(), resetAndSeed({seed, stock}), getLotsSeed(), isHealthy()
    lib/errors.js    ApiError + helpers: validation(fields), notFound(code), conflict(code), forbidden(), unauthenticated(); errorHandler

    routes/api.js    /api/v1/* production routes for the mobile app (+ GET /ping)
```

Key design choices (also the ADR topics for the viva):
1. Event sourcing: `match_events` is append-only (`PRIMARY KEY (match_id, sequence)`,
   `event_id UNIQUE`). The score is **rebuilt from the log on every read**.
   Compensation = new signed event; originals never change.
2. Concurrency (NFR-3): reserve stock with one atomic statement
   `UPDATE variants SET stock = stock - $q, reserved = reserved + $q WHERE variant_id=$1 AND stock >= $q`
   inside a transaction (all items or none), then mock payment, then
   `reserved = reserved - q` on success, or give stock back on failure.
   Per-match event appends are serialized with `SELECT ... FOR UPDATE` on the
   `matches` row (or `pg_advisory_xact_lock`).
3. Idempotency: store `body_hash` (sha256 of canonical body) + stored response per
   client id (`event_id`, `order_id`, `request_id`, `(device_id, action_id)`).
   Same id + same body -> 200 with stored response; different body -> 409.
4. RBAC: policy-as-code matrix in `domain/rbac/`, JWT HS256 with
   `algorithms: ['HS256']` (rejects alg:none), tenant isolation -> 403 (never 404).
5. Sports as data: config JSON in `sports.config`; scoring model `event` /
   `innings` / `round` decides the math. Event names are looked up in
   `config.scoring_events`, never hard-coded.
6. Queue: Redis Streams (approved list) for order/roster domain events.
7. Receipts: PDF generated server-side with `pdfkit`, returned as base64.
8. Rate limiting only on `/api/v1/*`. `/audit/v1/*` and `/health` are exempt.

## 3. Global API conventions (spec 5.2), implemented once, reuse everywhere

- Error body for every non-2xx: `{"error":{"code","message","details":{}}}`.
  `VALIDATION_ERROR` must have `details.fields` = array of bad field names.
  Throw `ApiError`s from route handlers; Express 5 forwards async errors.
- **Validation order:** 1) schema/types -> 400, 2) referenced id missing -> 404,
  3) business rule -> 409 (402 for payment). First failing step wins.
- Ids: `^[A-Za-z0-9_.:-]{1,64}$`, stored and returned verbatim.
- Timestamps `YYYY-MM-DDTHH:MM:SSZ` (use `nowIso()`), dates `YYYY-MM-DD`.
- Money in paisa integers, currency `"PKR"`.
- 201 for first-time create/apply, 200 for reads and idempotent replays.
- Unknown fields are ignored. Body > 1 MB -> 413 `PAYLOAD_TOO_LARGE` (done in app.js).
- Never return 5xx for bad input (SQL injection strings, `<script>`): always
  parameterized SQL, validate types first.

Subtle rules that are easy to miss (read the spec section for each):
- **5.6 sports:** `sport_id` regex `^[a-z0-9_-]{2,40}$`; SQL-injection id -> 400.
  round model `best_of` must be odd. `draw_lots` always applied last.
  201 body: `{sport_id, status:"created", config:{...stored config}}`.
- **5.7 fixtures:** pure computation, stores nothing. RR match_id
  `RR-L{leg}-R{round}-M{i}`, global round numbers, withdrawals policies.
  Swiss round 1 exact (seed i vs i+m, last seed bye if odd); later rounds need
  **minimum total |score diff|** over rematch-free pairings (backtracking), bye
  to lowest score without a bye (tie: largest index), else 409 `NO_VALID_PAIRING`.
  Single elim seed order recursion `order(2k) = for s in order(k): [s, 2k+1-s]`.
  Double elim: `WR{r}M{i}`, `LR{r}M{i}` (2(k-1) rounds, total B-2 matches), `GF1`,
  `GF2` (`conditional:true`, `required` null until GF1 result).
- **5.9 events:** status derived from log; `sequence` 1-based; `match_version` =
  count after append; signature over the **request payload** canonical JSON.
  Innings limits -> 409 `INNINGS_COMPLETE`; round model -> 409
  `SERIES_ALREADY_DECIDED`; compensated events do not count. Overs string
  `"{balls div bpo}.{balls mod bpo}"`.
- **5.10 standings:** recursive `resolve(group)` restarting from the first
  criterion on every split; h2h only among the current group; NRR to 3 decimals;
  `resolved_by`; draw_lots ascending sha256 key; clinched/eliminated formula
  uses points only.
- **5.11 roster:** the 8 checks in exact order; loans auto-return via `as_of`
  (write the `loan_return` audit entry once); deferred state when the player's
  squad is in `matches_in_progress`.
- **5.12 store:** 20 concurrent buyers on stock 1 -> one 201, nineteen 409,
  stock 0, reserved 0. Receipt PDF text must contain the order_id and
  `PKR 4500.00`. `discount_minor = floor(subtotal*10/100)`.
- **5.13 RBAC:** see the matrix in the spec. Authorization runs before anything
  else. Probes return `{"authorized":true}`. Tampered / alg:none / expired -> 401.
- **5.14 offline sync:** sort by `queued_at` (ties: array order), results in
  request order, statuses `applied/duplicate/rejected`, resolutions
  `appended/rebased_append/skipped_duplicate/server_wins`, always HTTP 200.
